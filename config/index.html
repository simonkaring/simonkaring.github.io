Config

Fresh machine, same setup.

What I install on a new laptop, and the permission settings I give coding agents so they can move quickly without being able to push, rewrite history or delete work.

macOS

Apple silicon. Homebrew for everything, the App Store only for the two apps that live there.

Package manager

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Keep the whole install current with brew upgrade. To see what is actually on the machine, brew list --cask.

Windows

winget ships with Windows, so there is nothing to install first. WSL for anything that expects a Unix shell.

Package manager

winget is part of the App Installer on Windows 10 and 11.

winget upgrade --all
winget search vivaldi   # confirm the current ID before installing

Install everything

Linux

Debian and Ubuntu with Flatpak for the graphical apps. Other distributions swap apt for dnf or pacman.

Base system

sudo apt update && sudo apt upgrade -y
sudo apt install -y git curl jq build-essential

Flatpak setup & apps (all in one)

Set up Flatpak, add Flathub, and install all graphical applications:

sudo apt install -y flatpak && \
flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo && \
flatpak install -y flathub \
  com.vivaldi.Vivaldi \
  com.visualstudio.code \
  com.discordapp.Discord \
  com.slack.Slack \
  com.spotify.Client \
  org.qbittorrent.qBittorrent \
  com.bitwarden.desktop

04

Coding agents

One permission baseline, applied to every agent I run.

Agents are most useful when they can read, search, test and commit without stopping to ask, and least useful when they can publish, rewrite history or delete work. The same three rules hold across tools:

Allow

  • Read, search, list
  • git status, add, commit, diff, log, show
  • Tests and builds

Ask

  • Installing packages
  • Adding dependencies

Deny

  • git push, reset --hard, clean -fd
  • Deleting branches
  • rm -rf, publish, docker push

Antigravity CLI

~/.gemini/antigravity-cli/settings.json

{
  "agentMode": "accept-edits",
  "colorScheme": "dark",
  "permissions": {
    "allow": [
      "command(git status)",
      "command(git add)",
      "command(git commit)",
      "command(git diff)",
      "command(git log)",
      "command(git show)",
      "command(ls)",
      "command(cat)",
      "command(grep)",
      "command(mkdir)",
      "command(jq)",
      "command(npm test)",
      "command(npm run build)",
      "command(cargo test)"
    ],
    "ask": [
      "command(npm install*)",
      "command(cargo add*)"
    ],
    "deny": [
      "command(git push*)",
      "command(git reset --hard*)",
      "command(git clean -fd*)",
      "command(git branch -D*)",
      "command(rm -rf *)",
      "command(npm publish*)",
      "command(docker push*)",
      "read_file(**/.env*)",
      "write_file(.git/*)"
    ]
  },
  "statusLine": {
    "command": "sh ~/.gemini/statusline.sh",
    "enabled": true,
    "stack_with_default": true
  },
  "toolPermission": "always-proceed",
  "verbosity": "low"
}

The status line reads the session JSON from stdin, so a small shell script can print the directory, branch, model, context used and remaining quota in one line.

opencode

~/.config/opencode/opencode.jsonc

{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": {
      "*": "ask",
      "git status": "allow",
      "git add": "allow",
      "git commit": "allow",
      "git diff": "allow",
      "git log": "allow",
      "git show": "allow",
      "npm test": "allow",
      "npm run build": "allow",
      "git push": "deny",
      "git push *": "deny",
      "git reset --hard *": "deny",
      "git clean *": "deny",
      "git branch -D *": "deny",
      "rm *": "deny",
      "mv *": "deny"
    }
  }
}

Everything unmatched falls back to ask, so a new command is a confirmation rather than a surprise. Terminal scrolling lives in ~/.config/opencode/tui.json.

Freebuff

~/.config/manicode/settings.json

{
  "mode": "DEFAULT",
  "adsEnabled": true,
  "freebuffCatalogReasoningEfforts": {
    "m-096e75164d": "high"
  }
}

Freebuff keeps its choices in a single settings file: the approval mode, whether ads are shown, the selected model key and per-model reasoning effort. Command approval happens in the session itself, so there is no allow and deny list to maintain. Keys as observed on my machine.
